# /verify — 对抗性验证技能

重要实现完成后，spawn一个独立子agent做对抗性验证。自己的检查不算数。

## 使用场景
- 重要功能实现后（发布器、流水线、定时任务等）
- 修复bug后确认修复有效
- 任何用户明确要求验证的场景

## 执行原则

### 核心理念
**你的自检不算数。** 你写的代码你会有盲区。必须用一个完全独立的agent来验证。

### 验证维度

1. **功能验证**: 是否实现了需求？边界情况处理了吗？
2. **负面验证**: 故意输入错误数据，系统会崩溃吗？
3. **回归验证**: 修改是否破坏了已有功能？
4. **环境验证**: 依赖是否都存在？配置是否正确？

### 执行方式

```python
# spawn一个子agent，给它的prompt要包含：
# 1. 需求描述
# 2. 实现路径
# 3. 具体的验证步骤
# 4. 预期结果
```

### Prompt模板
```
你是验证agent。你的任务是验证以下实现是否正确。

需求：{需求描述}
实现：{实现文件路径}
预期行为：{预期行为}

验证步骤：
1. 阅读实现代码
2. 用错误输入测试（至少3个edge case）
3. 检查错误处理
4. 确认输出格式符合预期

报告格式：
✅ 通过 / ❌ 失败 + 详细原因
```

### 验证完成后的行动
- 如果通过 → 告诉用户实现已验证
- 如果失败 → 修复问题后再次验证（最多重试3次）
