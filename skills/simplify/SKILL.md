# /simplify — 三维代码审查技能（v2，源自Claude Code simplify.ts）

对代码变更进行三个维度的并行审查：复用性、质量、效率。发现问题直接修复。

## 使用场景
- 刚完成一段代码修改，想检查质量
- 用户要求review代码
- 提交PR前的自检

## 执行流程

### Phase 1: 识别变更
```bash
git diff HEAD
git diff --cached
```

### Phase 2: 三维审查

#### 维度1: 代码复用（Reuse Review）
- 新函数是否与已有函数重复？
- 行内逻辑是否可以用已有utility替代？
- 手写的字符串处理、路径拼接、类型判断是否已有现成方案？
- 新代码是否可以放入已有的helper模块？

#### 维度2: 代码质量（Quality Review）
- **冗余状态**：重复的状态/缓存，可推导的值还额外存储
- **参数膨胀**：新加参数而非重构函数（→说明函数职责不清晰）
- **Copy-paste变体**：几乎相同的代码块应该统一（3行相似代码好过早抽象，但5行以上就该统一了）
- **泄漏抽象**：暴露了应该封装的内部细节
- **Stringly-typed code**：用原始字符串而非常量/枚举
- **无用注释**：解释WHAT（命名已做到）而非WHY的注释
- **未修改代码的改动**：不要给没改过的代码加docstring/注释/类型注解

#### 维度3: 效率审查（Efficiency Review）
- **不必要计算**：重复计算、重复文件读取、重复API调用
- **错过并发**：独立操作顺序执行而非并行
- **热路径膨胀**：启动/每次请求路径上新增的阻塞操作
- **No-op更新**：循环/定时器中无条件的状态更新（需加变更检测守卫）
- **TOCTOU反模式**：操作前检查存在性（check-then-act）
- **内存问题**：无界数据结构、缺少清理、事件监听泄漏
- **过度读取**：读整个文件但只用部分内容

### Phase 3: 修复问题
汇总三个维度发现，逐个修复。误报的跳过并说明原因。

## 输出
简短总结：修复了什么，或者确认代码没问题。如果有修复，列出每个修改。
